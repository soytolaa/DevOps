# Helm Kubernetes

This project contains Kubernetes resources managed using **Helm**.

Helm is a package manager for Kubernetes. It allows us to package Kubernetes manifests into reusable **Charts** and manage application deployments using configuration from `values.yaml`.

---

## 1. Helm Architecture

```text
Helm Chart
│
├── Chart.yaml
│       └── Chart metadata
│
├── values.yaml
│       └── Configuration values
│
└── templates/
        ├── deployment.yaml
        ├── service.yaml
        └── ...
                │
                ▼
              Helm
                │
                ▼
       Kubernetes Resources
```

---

## 2. Create a Helm Chart

Create a new chart:

```bash
helm create nginx-chart
```

Project structure:

```text
nginx-chart/
├── Chart.yaml
├── values.yaml
├── charts/
├── templates/
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── ingress.yaml
│   ├── serviceaccount.yaml
│   ├── _helpers.tpl
│   └── tests/
└── .helmignore
```

### Important files

| File          | Purpose                      |
| ------------- | ---------------------------- |
| `Chart.yaml`  | Helm chart metadata          |
| `values.yaml` | Default configuration        |
| `templates/`  | Kubernetes YAML templates    |
| `charts/`     | Chart dependencies           |
| `.helmignore` | Files ignored when packaging |

---

## 3. Chart.yaml

Example:

```yaml
apiVersion: v2
name: nginx-chart
description: A Helm chart for Kubernetes
type: application
version: 0.1.0
appVersion: "1.0.0"
```

### Version

```yaml
version: 0.1.0
```

This is the **Helm Chart version**.

### App version

```yaml
appVersion: "1.0.0"
```

This represents the version of the application being deployed.

---

## 4. values.yaml

`values.yaml` contains configuration used by the templates.

Example:

```yaml
replicaCount: 6

image:
  repository: nginx
  pullPolicy: IfNotPresent
  tag: ""

service:
  type: ClusterIP
  port: 80
```

The Deployment template can reference these values:

```yaml
spec:
  replicas: {{ .Values.replicaCount }}
```

Helm will render:

```yaml
spec:
  replicas: 6
```

---

## 5. Helm Template

Helm templates use Go template syntax.

Example:

```yaml
image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
```

If `values.yaml` contains:

```yaml
image:
  repository: nginx
  tag: "1.27"
```

Helm renders:

```yaml
image: "nginx:1.27"
```

## 6. Validate the Chart

Run:

```bash
helm lint ./nginx-chart
```

Expected result:

```text
1 chart(s) linted, 0 chart(s) failed
```

---

## 7. Render Templates

Before deploying, you can see the Kubernetes YAML generated by Helm:

```bash
helm template nginx ./nginx-chart
```

This command **does not deploy anything**.

It only renders the templates.

You can also search for replicas:

```bash
helm template nginx ./nginx-chart | grep replicas
```

---

## 8. Install the Chart

Install the chart:

```bash
helm install nginx ./nginx-chart
```

Here:

```text
nginx
  │
  └── Release name

./nginx-chart
  │
  └── Chart
```

Check installed releases:

```bash
helm list
```

Check Kubernetes resources:

```bash
kubectl get pods
kubectl get deployment
kubectl get service
```

---

## 9. Modify values.yaml

For example:

```yaml
replicaCount: 6
```

If the release already exists, apply the change with:

```bash
helm upgrade nginx ./nginx-chart
```

Check:

```bash
kubectl get deployment nginx
```

Expected:

```text
NAME    READY   UP-TO-DATE   AVAILABLE
nginx   6/6     6            6
```

Check Pods:

```bash
kubectl get pods
```

You should have 6 nginx Pods.

---

## 10. Override values with --set

You don't always need to modify `values.yaml`.

For example:

```bash
helm upgrade nginx ./nginx-chart \
  --set replicaCount=10
```

Now the Deployment will have:

```yaml
replicas: 10
```

This is useful for quick configuration changes.

## 11. Use Different Values Files

You can create environment-specific values:

```text
nginx-chart/
├── Chart.yaml
├── values.yaml
├── values-dev.yaml
├── values-uat.yaml
├── values-prod.yaml
└── templates/
```

Example:

### values-dev.yaml

```yaml
replicaCount: 1

image:
  repository: nginx
  tag: "1.27"
```

### values-prod.yaml

```yaml
replicaCount: 6

image:
  repository: nginx
  tag: "1.28"
```

Deploy development:

```bash
helm upgrade --install nginx ./nginx-chart \
  -f values-dev.yaml
```

Deploy production:

```bash
helm upgrade --install nginx ./nginx-chart \
  -f values-prod.yaml
```

Same Chart, different configuration.

---

## 12. Upgrade

After modifying the chart or values:

```bash
helm upgrade nginx ./nginx-chart
```

A useful pattern is:

```bash
helm upgrade --install nginx ./nginx-chart
```

This means:

```text
Release exists?
    │
    ├── Yes → upgrade
    │
    └── No  → install
```

## 14. Helm Release History

Helm keeps release history.

Check it:

```bash
helm history nginx
```

Example:

```text
REVISION    STATUS
1           deployed
2           superseded
3           deployed
```

---

## 15. Rollback

If a new deployment has a problem:

```bash
helm rollback nginx 1
```

Then check:

```bash
helm history nginx
kubectl get pods
```

Rollback allows you to return to a previous Helm revision.

---

## 16. Uninstall

Remove the Helm release:

```bash
helm uninstall nginx
```

Check:

```bash
helm list
kubectl get pods
```

The resources managed by the release will be removed.

## 18. Helm vs kubectl

### kubectl

Normally you apply Kubernetes YAML directly:

```bash
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
```

### Helm

Helm manages the complete application:

```bash
helm install nginx ./nginx-chart
helm upgrade nginx ./nginx-chart
helm rollback nginx 1
helm uninstall nginx
```

The important difference:

```text
kubectl
   │
   └── Kubernetes manifests

Helm
   │
   ├── Chart.yaml
   ├── values.yaml
   └── templates/
          │
          ▼
     Kubernetes manifests
```

---

## 19. Important Rule

Do **not** run:

```bash
kubectl apply -f Chart.yaml
```

`Chart.yaml` is Helm metadata, not a Kubernetes resource.

Use:

```bash
helm install nginx ./nginx-chart
```

or:

```bash
helm upgrade nginx ./nginx-chart
```

## 20. Basic Helm Workflow

The basic workflow is:

```text

     │
     ▼

     ▼

     │
     ▼

     │
     ▼
helm template
     │
     ▼
helm install
     │
     ▼
Kubernetes
     │
     ▼

     │
     ▼

     │
     ├──────────────┐
     ▼              ▼

     │
     ▼
helm uninstall
```

helm template nginx ./nginx-chart

# Install
helm install nginx ./nginx-chart

## 22. Key Concepts to Remember

```text
Chart
  = Kubernetes application package

Chart.yaml
  = Chart metadata

values.yaml
  = Configuration

templates/
  = Kubernetes YAML templates

Release
  = Installed instance of a Chart

Repository
  = Place where Helm Charts are stored
```

The most important Helm commands to remember:

```bash
helm create
helm lint
helm template
helm install
helm upgrade
helm history
helm rollback
helm uninstall
```
